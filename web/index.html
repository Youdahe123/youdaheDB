Storage engine

Sequential writes. Sorted reads. Nothing thrown away.

Every write is a sequential append to a log that is fsynced before it is acknowledged. Reads walk the memtable and then immutable sorted files, newest first, skipping whole files with bloom filters before touching the disk.

01

Durable by default

An acknowledged write is on disk. Kill the process with SIGKILL, restart, and the log replays everything back.

02

Immutable on disk

SSTables are written once and never modified. Compaction merges them and drops what is dead, writing to a temp file and renaming into place.

03

Reads that skip work

A bloom filter answers "definitely not here" in constant time with no disk I/O, so a miss costs one memory probe instead of a seek.

04

Replicated with Raft

Each range is its own Raft group of three replicas. Lose a node and the cluster keeps serving as long as a quorum survives.

05

Sharded by key range

Consistent hashing with virtual nodes, a key-range router, and ranges that split and merge as they grow.

06

Speaks Postgres

The PostgreSQL wire protocol, so psql, JDBC, psycopg and every ORM connect without changing a line.

Interfaces

Connect the way you already do

A psql-compatible shell, a scriptable CLI, an embeddable Rust library, and a browser console for the whole cluster.

shellcopy
# start a node
$ youdahedb-server --dir ./data --port 6380

# connect — psql muscle memory works
$ youdahedb
youdahedb=# \dt
youdahedb=# select id, email from users limit 5;

# one-shot, for scripts and CI
$ youdahedb -c "select count(*) from orders"
$ echo "select 1" | youdahedb
embedded — rustcopy
use youdahedb::LsmTree;

let mut db = LsmTree::open("./data")?;

db.put("user:1", "youdahe")?;
let v = db.get("user:1")?;
db.delete("user:1")?;

// sorted iteration across memtable + every SSTable
for (k, v) in db.scan("user:".."user;") {
    println!("{k} = {v}");
}
How it is built

No dependencies. None.

Every B-tree, hash, file format, protocol parser and thread pool is written here. Cargo.toml has an empty [dependencies] section and it stays that way.

0 crates The Rust standard library and nothing else — in the database and its tests.
1 binary The console ships inside the server. No asset directory, no build step, no node_modules.
3 replicas Per range, each its own Raft group — so sharding and replication stay orthogonal.
2 orderings WAL durable before memory mutates; SSTable durable before the log clears. That is the whole correctness argument.
